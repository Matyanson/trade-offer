app (MainManager):
    OrderManager (listens to on_trade):
        [events] on_trade (alpaca order event)
        [relations] parent Strategy - Order - alpaca Order



    StrategyMagager (listens to on_quote):
        Strategy tree:
            [events] on_quote (price change event)
            [relations] Strategy - child Strategies
    
    BudgetManager:
        [events] update_budget



events:

    [Strategy] create a new order -> [OrderManager] saves relations -> [on_trade] alpaca order filled -> [StrategyManager] update_budget -> [BudgetManager] update budget and pnl for strategy and its parent stratregies
    [on_quote] price change detected -> [StrategyMagager] trigger on_quote for all Strategies -> [Strategy] react to price change


classes:
    Order:
        is a wrapper to the alpaca order. it is easier to work with and provides properties like possition_qty that alpaca order does not.
        position_qty is derived from the on_trade event.
        purpose: alpaca order wrapper, linked to the on_trade event (OrderManager)

    Strategy:
        should provide structure to implement any possible trading strategy (focus on the logic only not the overhead of alpaca api or management). it provides events like on_quote and on_budget_update for easy implementation.
        every strategy can build on top of child Strategies or use Orders.
        purpose: provide useful structure for strategy implementation. linked to the on_quote event (StrategyMagager).
        currently, each Strategy implements update_budget on its own. however, I'm thinking it would be better if a manager did that and exposed on_budget_update. the manager would keep note all the Strategy child resources and update budget properties knowing which (id) child resource updated. For example out of 50 resources the one with id:some_id changed. we don't need to itterate over all of them.
    
    Budget:
        both Orders and Strategies have:
            budget_qty =        # total qty it can work with (should be a constant. But in the future version user can change it on the fly) (negative budget means budget for closing position, selling position)
            available_qty =     # unspent qty (= budget - filled - reserved)
            reserved_qty =      # qty that is reserved for pending orders (= budget - filled (for Orders))
            position_qty =      # qty contribution of the total position we have (filled - fees) 
            filled_qty = 0.0    # how much qty filled the order (can be partial)
    Pnl:
        each strategy has:
            total_cost_opened =     # sum of (position_qty * avg_filled_price) of all children resources (that opened a position)
            total_qty_opened =      # sum of position_qty of all children resources (that opened a position)
            total_cost_closed =     # sum of (position_qty * avg_filled_price) of all children resources (that closed a position)
            total_qty_closed =      # sum of position_qty of all children resources (that closed a position)
